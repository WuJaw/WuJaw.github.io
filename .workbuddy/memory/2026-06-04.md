# 2026-06-04

## GitHub Pages 构建失败修复

**问题**：GitHub Actions Jekyll 构建静默失败，日志在 `Rendering Markup:` 处截断。

**根因**：两篇"博客"类文章的代码块中包含未逃逸的 Liquid 模板代码：

1. **`_posts/2026-05-27-博客-jekyll-build.md`**：`{% for post in site.posts %}` 未包 raw，导致 Jekyll 在渲染时执行循环，遍历所有文章输出 HTML。

2. **`_posts/2026-05-29-博客-jekyll-toc-sidebar.md`**：代码块中的 `{{ content }}` 未逃逸，可能导致递归渲染。

**修复**：
- 两篇文章的 Liquid 示例代码都加了 `{% raw %}...{% endraw %}`
- `_config.yml` 恢复 `theme: jekyll-theme-primer`（本地 `_layouts/` 自动覆盖主题布局）

## 第二轮修复（构建仍失败）

遗漏了三处未逃逸的 Liquid 标签：

3. **`_posts/2026-05-27-博客-jekyll-build.md`** 第 61-72 行：展示 `post.html` 布局的代码块中有 `{{ page.title }}`、`{{ content }}`，未包 raw，`{{ content }}` 导致递归渲染死循环。

4. **`_posts/2026-05-28-博客-jekyll-image-path.md`** 第 21 行：表格中的 `{{ "/assets/x.png" \| relative_url }}` 未包 raw，且 `\|` 对 Liquid 是非法语法。第 119 行的 `{{ relative_url }}` 同理。

5. **`_posts/2026-06-04-博客-jekyll-liquid-escape.md`** 第 33 行：反引号内的 `{%` `%}` 和 `{{` `}}`，Liquid 会把 `{%` 识别为标签开始（即使后面跟着反引号），导致 unknown tag 错误。

**教训**：排查 Jekyll Liquid 逃逸问题时，要扫描所有文章，不能只看熟悉的几篇。`{{` 和 `{%` 在任何位置（包括反引号内、表格内）都会被 Liquid 优先处理。
