把个人博客从纯 HTML 迁移到 Jekyll，顺便记录下整个流程和用到的工具，方便以后回顾。

---

## 1 目录结构

```
WuJaw.github.io/
├── _config.yml              # Jekyll 配置
├── _layouts/                # 主题布局
│   ├── default.html         #   通用布局（含全部 CSS、搜索框）
│   └── post.html            #   文章布局（标题 + 日期 + TOC + 代码复制）
├── index.html               # 首页（分类卡片 + 实时搜索）
├── _posts/                  # 博客文章（Markdown）
├── assets/                  # 静态资源（图片统一放这里）
├── tools/                   # 在线工具 + 第三方依赖（es.exe 等）
├── python/                  # 自动化脚本（纯标准库，零依赖）
├── deploy.bat               # 一键部署入口
└── README.md
```

## 2 配置流程

### 2.1 `_config.yml` — Jekyll 核心

GitHub Pages 识别 Jekyll 的关键文件。当前完整配置：

```yaml
title: Wu-X
description: just as well
baseurl: ""
url: "https://wujaw.github.io"

theme: jekyll-theme-primer

# Markdown 渲染
markdown: kramdown
kramdown:
  input: GFM
  hard_wrap: false

# 文章 URL 格式：/posts/文章标题/
permalink: /posts/:title/

# 功能开关 — 设为 false 即隐藏对应模块
features:
  search:        true   # 首页搜索框
  site_nav:      true   # 左侧站点目录（分类+文章列表）
  toc:           true   # 右侧文章大纲（TOC）
  copy_button:   true   # 代码块复制按钮

# 隐藏分类 — 列在此处的分类不会出现在首页
hidden_categories:
  - 博客1

# 排除不编译的文件
exclude:
  - README.md
  - Gemfile
  - Gemfile.lock

plugins:
  - jekyll-feed
```

几个要点：

- `theme: jekyll-theme-primer` — 声明主题以满足 GitHub Pages 要求，但实际布局由 `_layouts/` 覆盖，不依赖远程主题
- `features` — 集中控制博客功能开关，不想用的功能一行 `false` 就关掉
- `hidden_categories` — 简化后的首页用"分类卡片"展示文章，不想显示的类别放这里
- `permalink: /posts/:title/` — 中文标题的 URL 会被百分号编码，这是正常的

### 2.2 布局模板

**`_layouts/default.html`** 是全局骨架。当前设计是极简白底风格：

- 全部 CSS 集中写在这个文件里（不引入外部框架）
- 最大宽度 720px，居中排版
- 字体：系统默认中文字体（PingFang SC / Microsoft YaHei / -apple-system）
- 首页搜索框也在这里定义
- **没有页头 logo、没有页脚、没有导航栏、没有暗色模式**

**`_layouts/post.html`** 继承 default，在文章正文基础上附加：

- 标题 + 日期区域
- 右侧 TOC 目录面板（由 `features.toc` 控制开关）
- 代码块复制按钮（由 `features.copy_button` 控制开关）

```html
{% raw %}
---
layout: default
---
<div class="post-header">
  <h1>{{ page.title }}</h1>
  <span class="post-meta">{{ page.date | date: "%Y年%-m月%-d日" }}</span>
</div>
<div class="post-content">
  {{ content }}
</div>
{% endraw %}
```

### 2.3 首页 — 分类卡片 + 搜索

首页不是简单的文章列表，而是按 `category` 字段自动分组的**卡片视图**：

{% raw %}
```html
{% for category in site.categories %}
<div class="cat-card">
  <div class="cat-card-header">
    <span class="cat-name">{{ category[0] }}</span>
    <span class="cat-count">{{ category[1] | size }} 篇</span>
  </div>
  <ul class="cat-articles">
    {% for post in category[1] %}
    <li>
      <a href="{{ post.url }}">{{ post.title }}</a>
      <span>{{ post.date | date: "%Y-%m-%d" }}</span>
    </li>
    {% endfor %}
  </ul>
</div>
{% endfor %}
```
{% endraw %}

顶部搜索框是纯前端 JS 实现：监听 `input` 事件，实时过滤文章标题和分类名，空分类卡片自动隐藏。

新增文章后不用改首页，Jekyll 构建时自动归入对应分类卡片。

## 3 设计风格

白底极简，720px 最大宽度，系统默认中文字体。所有样式集中在 `_layouts/default.html`——不切 CSS 文件、不引入外部框架。

几个刻意的"减法"：

- **去掉了页头 logo** — 博客标题和描述不需要
- **去掉了页脚** — 版权声明、社交链接之类的不需要
- **去掉了导航栏** — 单页不需要导航
- **去掉了暗色模式** — 减少维护负担，不需要就别加

代码块通过 Rouge（Jekyll 内置）实现语法高亮，使用 Tommorow Night Eighties 配色主题。

## 4 写文章规范

1. 在 `_posts/` 下新建文件，命名：`YYYY-MM-DD-分类-标题.md`
2. 只需写正文，Front Matter 由 `deploy.bat` 自动补齐：

```markdown
---
layout: post
title: "文章标题"
date: 2026-05-27
category: 分类名
---

正文写在这里，标准的 Markdown 语法。
```

3. **图片方案**：Typora 写作时用 `![desc](../assets/xxx.png)` 实时预览，push 前 `deploy.bat` 自动转为 `<img src="/assets/xxx.png" alt="desc">`；继续编辑用 `typora.bat` 转回来
4. 双击 `deploy.bat` 一键部署，GitHub Pages 1-2 分钟生效

## 5 工具链

| 工具 | 用途 |
|------|------|
| **Jekyll** | 静态站点生成器，GitHub Pages 原生支持 |
| **kramdown** | Markdown 渲染引擎，兼容 GFM 语法 |
| **Rouge** | 代码语法高亮，Jekyll 内置 |
| **Liquid** | Jekyll 模板语言，循环、条件、变量全靠它 |
| **GitHub Pages** | 免费托管，push 即部署 |
| **deploy.bat** | 一键部署脚本：标题自动编号 → 补齐 Front Matter → 图片路径转换 → git commit & push |
