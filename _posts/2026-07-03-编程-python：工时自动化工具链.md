把从周报 Excel 到工时系统提交的整个流程自动化——包括项目编码自动补全、Cookie 获取、接口对接、启动优化和 PyInstaller 打包，汇总成一篇。

源码：[submit_work_hours.py](https://github.com/WuJaw/WuJaw.github.io/blob/master/python/submit_work_hours.py)、[export_projects.py](https://github.com/WuJaw/WuJaw.github.io/blob/master/python/export_projects.py)。

## 1 背景

公司工时系统是一个 Vue 3 + Element Plus 的 Web 应用，每天要手动登录填报。工作内容已经写在周报 Excel 里，重复填写效率低下，于是写了 Python 脚本自动完成提交——从 Excel 解析到接口提交一步到位。

## 2 接口分析

### 2.1 抓包方式

工时系统在内网，外部工具无法直接访问。通过浏览器 F12 Console 注入拦截器来捕获请求：

```javascript
(function(){
  var origOpen = XMLHttpRequest.prototype.open;
  var origSend = XMLHttpRequest.prototype.send;
  XMLHttpRequest.prototype.open = function(){
    var xhr = this;
    xhr.addEventListener('readystatechange', function(){
      if(xhr.readyState === 4){
        console.log('[POST] ' + xhr._u + ' => ' + xhr.status);
        console.log('  Response: ' + xhr.responseText.substring(0, 500));
      }
    });
    origOpen.apply(this, arguments);
    xhr._u = arguments[1];
  };
  XMLHttpRequest.prototype.send = function(body){
    console.log('Body: ' + body);
    return origSend.apply(this, arguments);
  };
  console.log('Interceptor started');
})();
```

### 2.2 关键接口

| 接口 | 说明 | 请求体 |
|------|------|--------|
| `POST /api/dailyReport/add` | 新建日报 | 数组格式 |
| `POST /api/dailyReport/update` | 更新日报 | 对象格式，需带 `id` |
| `POST /api/dailyReport/list` | 查询日报列表 | 分页参数 |

关键差异：`add` 接口接收**数组**，`update` 接口接收**对象**且必须带 `id` 字段，否则服务端 SQL 会因缺少 `id` 限定查出大量重复记录，报 `Expected one result (or null) to be returned by selectOne()` 错误。

### 2.3 认证方式

认证通过 Cookie 完成，Cookie 格式：

```
TMS_SESSION_ID=xxxx; rememberMe=xxxx; token=111
```

其中 **`token=111` 就是用户 ID**。服务端 `dailyReport/add` 接口不校验 payload 里的 `userId`，直接以 Cookie 对应的 session 身份提交。如果 Cookie 是别人的，即使 payload 填了自己的 userId，日报也会提交到别人名下。

因此必须确保 Cookie 中的 `token` 字段和提交的 userId 一致。脚本会自动从 Cookie 的 `token=` 字段提取 userId，并通过 `/api/dailyReport/list` 反查用户姓名。

## 3 周报 Excel 结构

周报文件结构如下（Sheet 名：`周报`），G 列「约最大天数」表示当天工时系数：

| 星期 | 日期 | 工作状态 | 项目编码 | 工作内容 | 备注 | 约最大天数 |
|------|--------|---------|---------|---------|------|----------|
| 周一 | 2026-01-05 | 办公 | RD240012 | 对接需求定义 | | 1 |
| 周二 | 2026-01-06 | 办公 | RD240009 | 软著材料编写 | | 1 |
| ... | ... | 法定假 | | | 休息 | |
| (空) | (空) | 办公 | RD240005 | 半天开发 | | 0.5 |

「约最大天数」列：`1` = 全天（8 小时），`0.5` = 半天（4 小时），留空按全天处理。该列通常为空，只有零星半天工时（如「事假 + 半天办公」同日拆分）才会填 `0.5`。

每周之间有"本周工作重点"和"下周工作计划"分隔行，脚本解析时会自动跳过。**注意不同人的周报布局不同**——有人把分隔行写在 A 列、有人写在日期列（B 列），甚至有人写的是"本周工作重点"而非"本周工作计划"。脚本对前 3 列统一检测这些分隔短语，避免分隔行被误当成数据行。

工作状态分类：

- **工作日**：`办公`、`出差`、`外勤` → 按「约最大天数」提交工时（全天 `1` = 8 小时，半天 `0.5` = 4 小时）
- **休息日**：`法定假`、`周六`、`周日`、`年假`、`病假`、`调休` 等 → 跳过不提交

### 3.1 日期格式兼容

不同人的周报 Excel 日期格式可能不同：

| 格式 | 示例 | 来源 |
|------|------|------|
| datetime 对象 | `2026-01-05 00:00:00` | pandas 自动解析 |
| 横杠字符串 | `2026-01-05` | 部分手动填写的 Excel |
| 点分隔字符串 | `2026.1.1` | 部分人的 Excel |

脚本统一将 `.` 和 `/` 替换为 `-`，再用 `strptime` 解析，确保输出 `YYYY-MM-DD` 标准格式。

## 4 周报预处理：项目编码自动填写

周报 Excel 的"项目编码"列（D 列）经常留空，手动逐行填写费时。实际工作内容里包含项目关键词（如"输液"、"床垫"、"蜂巢"等），可以先跑一个脚本根据关键词自动匹配项目编码，批量补全后再交给工时填报脚本。

### 4.1 映射规则

根据公司项目列表，建立关键词到项目编码的映射：

| 关键词 | 项目编码 | 项目名称 |
|--------|----------|----------|
| 婴儿标签、bg13 | RD240008 | 婴儿防盗系统 |
| 输液、夹断、bg22 | RD240003 | 输液监测系统 |
| 蜂巢、星链、PCIE、at32、华为、海康 | RD250002 | 全网通数分平台 |
| 床垫、BWS | RD240005 | 生命体征监测床垫系统 |
| 送检、软著、CE 认证、ch592、其他 | RD240009 | 物联网定位平台 |

匹配顺序：**先命中先生效**，未命中任何关键词则使用默认编码 `RD240009`。

### 4.2 实现代码

```python
import openpyxl
import shutil

src = r'D:\SVN2\docx\周报\办公室周报2026-吴潇.xlsx'
shutil.copy2(src, src + '.bak')  # 备份原文件

wb = openpyxl.load_workbook(src)
ws = wb.worksheets[0]

# 关键词 → 项目编码（顺序即优先级，先匹配先生效）
rules = [
    (['婴儿标签', 'bg13', 'BG13'], 'RD240008'),
    (['输液', '夹断', 'bg22', 'BG22'], 'RD240003'),
    (['蜂巢', '星链', 'PCIE', 'pcie', 'at32', 'AT32', '华为', '海康'], 'RD250002'),
    (['床垫', 'BWS'], 'RD240005'),
]
default_code = 'RD240009'

for r in range(4, ws.max_row + 1):
    status = ws.cell(r, 3).value
    code = ws.cell(r, 4).value
    # 只处理办公/外勤/出差，且项目编码为空的行
    if not status or str(status).strip() not in ('办公', '外勤', '出差'):
        continue
    if code and str(code).strip():
        continue

    # 合并工作内容 + 备注进行匹配
    content = str(ws.cell(r, 5).value or '')
    note = str(ws.cell(r, 6).value or '')
    text = content + ' ' + note

    matched_code = default_code
    for keywords, project_code in rules:
        if any(kw in text for kw in keywords):
            matched_code = project_code
            break

    ws.cell(r, 4).value = matched_code

wb.save(src)
```

### 4.3 关键设计

**匹配优先级**：规则列表的顺序决定优先级。例如某天工作内容同时包含"输液"和"婴儿标签"，`婴儿标签` 规则排在前面会先命中。

**跳过已有编码**：如果某行已手动填了项目编码，脚本不会覆盖，只补空缺行。

**备份机制**：修改前自动创建 `.bak` 备份，万一匹配错误可以回退。

### 4.4 踩坑：D 列数据验证

原始 Excel 的 D 列（项目编码）被误加了与 C 列相同的下拉验证规则：

```
C4:D7  →  list: "办公,外勤,出差,周六,周日,调休,法定假,年假,病假,婚假,事假,丧假,其他"
```

导致 D 列单元格显示工作状态下拉，而非自由输入项目编码。需要用 openpyxl 将数据验证范围从 `C:D` 改为仅 `C`：

```python
import re

wb = openpyxl.load_workbook(src)
ws = wb.worksheets[0]
dv = ws.data_validations.dataValidation[0]

# 将 C4:D7 拆为 C4:C7，删除纯 D 列范围
new_parts = []
for part in str(dv.sqref).split():
    if ':' in part:
        start, end = part.split(':')
        c1 = re.match(r'[A-Z]+', start).group()
        c2 = re.match(r'[A-Z]+', end).group()
        if c1 == 'C' and c2 == 'D':
            r1 = re.search(r'\d+', start).group()
            r2 = re.search(r'\d+', end).group()
            new_parts.append(f'C{r1}:C{r2}')
        elif c1 == 'C':
            new_parts.append(part)
        # D 列范围直接丢弃
    else:
        col = re.match(r'[A-Z]+', part).group()
        if col == 'C':
            new_parts.append(part)

dv.sqref = ' '.join(new_parts)
wb.save(src)
```

## 5 脚本实现

### 5.1 启动加速：三阶段加载

脚本将操作分为三个阶段，**先把所有用户输入收完，再加载重模块**：

| 阶段 | 操作 | 延迟 |
|------|------|------|
| 阶段 1（秒出） | 读 cookie → 确认 Excel 路径 → 输日期范围 | <1s |
| 阶段 2（按需） | 弹 tkinter 文件对话框 | 仅首次选新文件 |
| 阶段 3 | `import pandas/requests` + 网络验证 | 输完才执行 |

关键技巧：`pandas` 和 `requests` 改为**懒加载**（函数内 `import`），不在脚本顶部导入，避免启动时 3–5 秒的模块加载阻塞用户输入。

### 5.2 Cookie 输入：剪贴板读取

Windows 控制台 `input()` 有缓冲区限制，长 Cookie 字符串（含 `rememberMe` 加密数据，几百字符）粘贴时会被截断。

解决：输入 Cookie 时直接回车，脚本通过 PowerShell `Get-Clipboard` 读取系统剪贴板，完整无截断：

```python
def read_clipboard():
    """从 Windows 剪贴板读取文本"""
    import subprocess
    result = subprocess.run(
        ['powershell', '-NoProfile', '-Command', 'Get-Clipboard'],
        capture_output=True, text=True, timeout=5
    )
    return result.stdout.strip()

def input_cookie(prompt='Cookie: '):
    print('（浏览器复制 Cookie 后直接回车粘贴，或手动输入）')
    raw = input(prompt).strip()
    if raw:
        return raw
    # 回车 → 读剪贴板
    clip = read_clipboard()
    if clip:
        print(f'  已读取 ({len(clip)} 字符): {clip[:50]}...{clip[-20:]}')
        return clip
    return ''
```

使用流程：
1. 浏览器 F12 → Network → 复制完整 Cookie（Ctrl+C）
2. 运行脚本 → Cookie 提示时**直接回车**
3. 自动读取剪贴板，显示首尾供确认

备用方案：ctypes 调用 Win32 API（`OpenClipboard/GetClipboardData`），在 PowerShell 不可用时使用。

### 5.3 用户身份自动识别

从 Cookie 的 `token=` 字段自动提取 userId，再通过 API 反查姓名：

```python
def extract_uid_from_cookie(cookie_str):
    for part in cookie_str.split(';'):
        part = part.strip()
        if part.startswith('token='):
            val = part[6:].strip()
            if val.isdigit():
                return int(val)
    return 0

def detect_user(cookie, user_id):
    result = api_post(cookie, '/api/dailyReport/list',
                      {'pageNum': 1, 'pageSize': 1, 'userId': user_id})
    if result.get('code') == '200':
        items = result['info'].get('list', [])
        if items:
            return items[0]['userCompellation']
    return ''
```

也支持命令行参数覆盖：`--uid 114 --name 唐嘉伟`。

### 5.6 PyInstaller 兼容

打包为 exe 后，`__file__` 指向临时解压目录（`sys._MEIPASS`），每次运行路径不同，导致 cookie 文件丢失。修复：

```python
if getattr(sys, 'frozen', False):
    APP_DIR = os.path.dirname(sys.executable)  # exe 所在目录
else:
    APP_DIR = os.path.dirname(os.path.abspath(__file__))  # 脚本目录
```

`cookie.txt`、`last_path.txt` 都保存在 exe 同目录，稳定可靠。

```

    ↓
读 cookie.txt → 提取 token=uid → 确认 Excel 路径 → 输日期范围
```

## 7 踩坑记录

### 7.1 已审核记录不可修改

提交时报 `程序异常，稍后重试`，实际 API 返回的是 `info: "日报记录已审核不可修改删除!"`。原代码只看 `msg` 字段，把真实原因藏掉了。

修复：
1. 错误提示优先显示 `info`（服务端真实原因），其次 `msg`
2. `auditing == 1` 时自动跳过，输出 `SKIP` 而非尝试提交

### 7.2 Cookie 粘贴截断

Windows 控制台 `input()` 缓冲区有限，长 Cookie 粘贴时后半段丢失。表现为 Cookie 验证失败，但手动检查发现内容不完整。

修复：通过 PowerShell `Get-Clipboard` 读取剪贴板，绕过控制台缓冲区限制。

### 7.3 多用户串号

最初 `USER_ID=111` 硬编码，别人用脚本时日报全提交到了吴潇名下。根本原因：

1. 服务端没有"获取当前用户"接口
2. `add` 接口信任 payload 中的 `userId`，不做身份校验
3. 但 Cookie 中的 session 决定了实际归属——用谁的 Cookie 登录就是谁的

修复：从 Cookie 的 `token=` 字段提取真实 userId，确保身份一致。

### 7.4 Excel 日期格式不兼容

唐嘉伟的 Excel 日期是字符串 `"2026.1.1"`（点分隔），字符串比较时 `"." > "-"` 导致日期范围过滤失败，输出"范围内无记录"。

修复：统一将 `.` 和 `/` 替换为 `-`，再用 `strptime` 解析为标准 `YYYY-MM-DD`。

### 7.5 update 接口 selectOne 报错

用 `/api/dailyReport/update` 创建新记录（不带 `id`），服务端返回：

```json
{"code":"202","msg":"程序异常，稍后重试","info":"Expected one result (or null) to be returned by selectOne(), but found: 12497"}
```

解决：区分 `add`（新建，不带 `id`）和 `update`（更新，带 `id`）两个接口。

### 7.6 add 请求体是数组

`add` 接口的请求体是 JSON **数组**，每个元素代表一条日报；`update` 是单个**对象**。第一次用对象格式调 `add` 被服务端静默忽略。

### 7.7 半天工时被静默漏报

最初 `duration` 写死为 `8`，且日期为空的行直接 `continue` 跳过。周报里「事假 + 半天办公」是同一天的拆分写法——上午事假那行填了日期，下午半天办公的行日期留空、G 列标 `0.5`。结果这两条半天记录既没按系数算工时（系数没读），又因为没日期被直接丢弃，工时系统永远缺这半天，还毫无报错。

修复（见 `read_excel`）：

1. 读 G 列「约最大天数」作为工时系数：`duration = round(frac * 8)`。全天 `1` → 8 小时，半天 `0.5` → 4 小时，缺省按全天。
2. 日期缺失时沿用上一行有效日期（半天行跟随前一行事假同日），不再因空日期被跳过。

实测：`办公室周报2026-吴潇.xlsx` 中 `2026-07-06`、`2026-07-31` 两条半天记录被正确解析为 `duration=4`，总记录数也补齐。

### 7.8 分隔行误判导致 date=None 崩溃

梅龙的周报把"本周工作重点"写在**日期列（B 列）**，而脚本原本只对"本周工作计划"做匹配、且只查列 0/列 1。结果"本周工作重点"分隔行没被跳过，被当成数据行；其日期格是文字（不可解析），旧的日期回退逻辑又有缺口，记录带着 `date=None` 进入列表，最后 `records[0]['date'][:4]` 抛 `TypeError: 'NoneType' object is not subscriptable`。

修复（见 `read_excel`）：

1. 分隔行检测覆盖前 3 列，匹配集合同时包含 `本周工作重点` 与 `本周工作计划`（不同人写法不同）。
2. 日期解析失败或缺失时回退到上一行有效日期；若连上一行都没有则跳过该行——保证 `date` 永不为 `None`。

实测：梅龙文件从误报的 189 条（含 30 条脏分隔行）变为 159 条有效工时，首条日期正常、不再崩溃。
