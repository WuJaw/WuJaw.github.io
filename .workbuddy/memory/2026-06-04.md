## es.exe 参数修复：-name → -full-path-and-name

- `es.exe -name fname` 默认只输出裸文件名（如 `00README.md`），不含路径
- `os.path.isfile("00README.md")` 在当前工作目录找不到，导致每次搜索都"未找到"
- 改为 `es.exe -full-path-and-name fname`，输出完整绝对路径（如 `C:\Users\wuergou\Desktop\xxx.png`）
- `-full-path-and-name` + `-name` 组合会产生两列输出（文件名 + 路径），解析更麻烦
- 去掉 `-name` 后搜索范围略宽（匹配路径中任意位置），但 `os.path.isfile` 能兜底过滤

## 行内代码（inline code）跳过修复

**问题**：`fix_img_path.py` 只跳过了围栏代码块（` ``` `），没有跳过行内代码（`` ` ``）。博客教学文章中的 `` `![desc](../assets/xxx.png)` `` 被当成真实图片去搜索 `xxx.png`。

**根因**：fence 分割后，非代码 chunk 以 ` ``` ` 行开头（上一个块的关闭标记）。`INLINE_CODE` 正则把 ` ``` ` 的第三个反引号当成了行内代码的开始，吞掉了真正的行内代码边界，导致 `` `![desc](xxx)` `` 被解析为"行内代码外"的图片。

**修复**：
1. 新增 `INLINE_CODE = re.compile(r'\`[^\`]+\`')` 正则
2. 新增 `_process_chunk()` 函数，在 fence 分段之后再做行内代码分段，图片替换只作用于行内代码外的内容
3. 新增 `LEADING_FENCE = re.compile(r'^\`\`\`[^\n]*\n')` ，在处理前临时去掉 chunk 开头的 ` ``` ` 行，处理完再放回去
4. `fix_img_reverse.py` 同步加上相同的行内代码保护

**验证**：`web` 脚本全部 17 篇文章"无需修改"，`reverse` 脚本也正确跳过教学示例，只转换真实图片。
