## 1 项目概述

### 1.1 基本信息

| 项目属性 | 值 |
|---|---|
| 项目名称 | infusion_monitorG3.0 |
| 版本号 | V2.20.0.21（主版本 2，中版本 0x20，子版本 0） |
| MCU 芯片 | Silicon Labs EFR32FG14P231F128GM32（Flex Gecko, Series 1, Config 4） |
| Flash 容量 | 128 KB |
| RAM 容量 | 16 KB |
| SDK 版本 | Gecko SDK Suite v2.7 |
| 编译器 | GNU ARM GCC v4.9.3 |
| 射频库 | RAIL Library |
| 基频 | 610 MHz（Sub-GHz） |

### 1.2 功能简介

本固件运行于输液监控器设备端，通过 Sub-GHz 无线电与基站通信。核心功能包括：

- 输液状态实时监控（电容式传感器检测液滴）
- 与基站的 A 同步建立通信链路
- 周期性心跳数据上报
- 输液事件上报（低电量、无液体提醒、输液结束等）
- 电机夹紧/松开控制（输液管路控制）
- 开盖检测与自动回收
- OTA 远程固件升级
- 低功耗管理（EM2 深度睡眠）

## 3 各模块详细说明

### 3.1 主程序 — main.c

系统启动入口，完成硬件初始化序列并进入主工作循环。

**初始化流程（按执行顺序）：**

```
1.  CHIP_Init()            — 芯片初始化（errata 修复）
2.  halInit()              — HAL 层初始化
3.  BSP_Init(BSP_INIT_BCC) — 板级支持包初始化
4.  radioInit()            — RAIL 射频初始化
5.  init_gpio()            — GPIO 引脚配置
6.  bat_init()             — 电池检测引脚初始化
7.  paraInit()             — 系统参数初始化
8.  initLetimer()          — LETIMER 低功耗定时器初始化
9.  LED 闪烁 500ms         — 上电指示
10. ENTER_EM2()            — 进入 EM2 深度睡眠
11. initCryotimer()        — Cryotimer 初始化
12. 复位原因判断            — 区分上电复位与异常复位
13. 开机自检               — 电机正反转测试
14. init_acmp()            — 模拟比较器初始化
15. init_lesense()         — LESENSE 传感器初始化
16. LESENSE_ScanStart()    — 启动电容扫描
17. initWDOG()             — 看门狗初始化
```

**主循环逻辑：**

```c
sync.work_mode = action_mode;  // 初始进入 action 模式
while (1) {
    switch (sync.work_mode) {
        case action_mode:  action_mode_process();  break;
        case normal_mode:  normal_mode_process();  break;
        default:           // 错误状态，LED 快闪
    }
}
```

**关键逻辑：**
- 上电/掉电复位（PORST/AVDDBOD/DVDDBOD/DECBOD）时执行开机自检（电机伸出再回收）
- 非上电复位时从 Flash USERDATA 恢复电机静态状态
- 关闭 SWD 调试引脚以降低功耗

### 3.4 app_driver 模块

#### 3.4.1 电池检测 — bat.c / .h

电池电压采集与低电量检测。引脚 PD15（BATON）控制电池检测供电。

- `get_voltage()`：ADC 采样 3 次取中位数，换算电压值
- `bat_voltage_check()`：连续采样 3 次取平均，低于 14.0V 触发低电量事件
- 换算公式：`voltage = adc12_value * 500 / 4096`（2.5V 参考，分压 x2，扩大 100 倍）

#### 3.4.2 电容传感器与外设控制 — cap_sensor.c / .h

GPIO 初始化、电机控制、蜂鸣器、电容传感器（LESENSE）初始化及数据处理。

**GPIO 引脚定义：**

| 引脚 | 端口 | 用途 |
|---|---|---|
| LED | PF3 | LED 指示灯 |
| BEEP | PF2 | 蜂鸣器 |
| CAP | PA0 | 电容传感器通道 |
| INA | PB13 | 电机驱动 A |
| INB | PB12 | 电机驱动 B |
| nSLEEP | PD14 | 电机驱动休眠控制 |
| KEY | PC11 | 按键 1（输液管检测） |
| KEY2 | PB11 | 按键 2（开盖检测） |
| KEY3 | PD13 | 按键 3（到位检测） |

**主要函数：**
- `init_gpio()`：GPIO 初始化，注册 KEY2/KEY3 中断回调
- `motor_ctl(flag)`：电机伸出（flag=1）或回收（flag=2），Cryotimer 延时控制
- `beep_on(f)`：三段式蜂鸣鸣叫
- `init_acmp()`：模拟比较器初始化（电容传感模式）
- `init_lesense()`：LESENSE 初始化（周期扫描，PRS 通道 0）
- `determination()`：电容传感器数据处理，检测输液管状态变化

#### 3.4.5 Sub-GHz 无线通信 — subg.c / .h

实现与基站之间的所有 Sub-GHz 无线数据收发逻辑。

**RF 接收窗口宏：**

| 宏名 | 值 | 说明 |
|---|---|---|
| `RF_RWIN_500US` | 0xF5 | 500 微秒窗口 |
| `RF_RWIN_1MS` ~ `RF_RWIN_5MS` | 5~25 | 1~5 毫秒窗口 |
| `RF_RWIN_50MS` | 250 | 50 毫秒窗口 |
| `RF_RWIN_ACTION` | 0xFE | Action 专用窗口 |
| `RF_RWIN_RAND` | 0 | 随机延时 |

**主要函数：**
- `send_data_to_base(command)`：向基站发送数据（填充 txbuf → 组帧 → RAIL 发送）
- `deal_beacon_data()`：处理 Beacon 数据（校验归属基站、处理通知）
- `SubgReceivePacketOpenWindow(timeout, rxBuf)`：开窗接收
- `rcv_data_from_base(timeout, power)`：接收基站数据
- `recv_beacon_process()`：Beacon 接收处理（成功缩小窗口，失败逐步增加补偿）
- `deal_action_data()`：处理 Action 回复（校验 Sequence、设置时间偏移）
- `device_upload_data()`：数据上报

#### 3.4.6 同步状态管理 — sync.c / .h

**核心数据结构 SYNC_STRU：**

```c
typedef struct {
    uint8_t event;               // 同步事件
    uint8_t work_mode;           // 工作模式
    uint8_t sequence;            // 通信序列号
    uint8_t event_sequence;      // 事件序列号
    uint8_t trigger_type;        // A 同步类型
    uint8_t lost_beacon_times;   // 丢失 Beacon 次数
    volatile uint8_t rf_channel; // RF 通道
    uint8_t ipart_no[4];         // 输液监控器 Part No
    uint8_t bpart_no[4];         // 基站 Part No
    volatile uint8_t reminder;   // 无液体提醒标志
    int8_t rxRssi;               // 接收信号强度
    uint32_t motor_state;        // 电机运动状态
    uint32_t motor_static_state; // 电机静态状态
    uint8_t oc_flag;             // 开盖标志
} SYNC_STRU;
```

**工作模式：**

| 模式 | 值 | 说明 |
|---|---|---|
| `sleep_mode` | 0x00 | 睡眠模式 |
| `normal_mode` | 0x01 | 正常工作模式 |
| `action_mode` | 0x02 | A 同步模式 |
| `send_mode` | 0x04 | 发送模式 |
| `test_mode` | 0x05 | 测试模式 |

**`paraInit()` 参数初始化：**
1. 从 USERDATA 读取输液监控器 Part No（必须以 0x89 开头）
2. 以 Part No 末字节为种子初始化随机数
3. 从 Flash 读取 OTA 版本号
4. 初始化事件、工作模式、序列号、通道
5. 设置触发类型为上电

#### 3.4.7 任务调度 — task.c / .h

**TASK_STRU 结构体包含：** 1 秒时基、500ms 时基、RTCC 计时、随机计数、上传数据时基、电量检测时基、复位计数等。

**任务 ID 定义：**

| 任务 ID | 值 | 说明 |
|---|---|---|
| `task_ask_action` | 0x02 | 发送 A 请求 |
| `task_rcv_action` | 0x04 | 接收回复 |
| `task_rcv_beacon` | 0x05 | 接收 Beacon |
| `task_send_iheartbeat` | 0x07 | 发送心跳 |
| `task_check_bat` | 0x09 | 电压检测 |
| `task_upload_data` | 0x0C | 上传数据 |

**`action_mode_process()` A 同步模式：**
1. 初始化 → 发送 A 请求 → 开窗接收回复
2. 成功则切换到 normal_mode
3. 失败则随机延时重试，超时 300 次重启

**`normal_mode_process()` 正常工作模式：**
1. 接收 Beacon → 失败超 5 次切回 action_mode
2. 周期性电池检测（每 120 次）
3. 数据上报（gFlag 触发）
4. 事件发送（等待 ACK，最多重发 5 次）
5. 每轮循环：喂狗 → 关闭 Radio → 进入 EM2

### 3.5 user_driver 模块

| 文件 | 用途 |
|---|---|
| `adc.c / .h` | ADC 初始化和中断处理，电池电压采集（AUXHFRCO 1MHz，2.5V 参考，12 位） |
| `cryotimer.c / .h` | 超低功耗定时器，电机延时控制（ULFRCO，8ms 周期） |
| `exti.c / .h` | GPIO 中断回调（KEY2 开盖检测 → 电机回收，KEY3 到位检测 → 停止电机） |
| `flash.c / .h` | Flash USERDATA 页读写（电机状态存储） |
| `hdelay.c / .h` | 微秒级软件延时 |
| `letimer.c / .h` | LETIMER0 主时基（LFXO 32768Hz，1 秒周期），RF 接收窗口定时 |
| `rtcc.c / .h` | RTCC 实时时钟（1 秒 tick），数据上传周期控制和随机延时 |
| `wdog.c / .h` | 看门狗（ULFRCO，约 32 秒周期，EM2 运行） |

**LETIMER 中断处理（核心时基）：**
- `sleep_mode`：10 秒唤醒
- `action_mode`：前 10 次每 6 秒请求，之后每 30 秒
- `normal_mode`：每 30 秒触发 Beacon 接收

**`set_offset_time()` 时间偏移校准：** 从 Action 回复中提取基站时间基准，计算补偿值调整 LETIMER 计数器，实现时间同步。

## 5 主要功能流程

### 5.1 系统启动流程

```
上电
  │
  ▼
CHIP_Init → halInit → BSP_Init → radioInit → init_gpio
  │
  ▼

  ▼

  ▼

```

## 6 RF 通信分析

### 6.1 协议帧结构

发送帧格式：

```
[0]    : 帧长度 = txbuf[0] + 2
[1..N] : 协议数据 (来自 subg.txbuf)
```

`subg.txbuf` 结构（以 A 请求为例）：

```
txbuf[0]   : 数据长度
txbuf[1]   : 命令码
txbuf[2-5] : 输液监控器 Part No (4 字节)
txbuf[6-9] : 基站 Part No (4 字节)
txbuf[10]  : 状态/事件类型
txbuf[11]  : 序列号
txbuf[12]  : RSSI/电压值
...
```

### 6.2 通信时序与同步机制

**时间同步核心：** LETIMER0（32768Hz LFXO）

- 1 秒时基：LETIMER COMP0 中断每秒触发
- 时间偏移校准：Action 回复中携带基站时间基准，通过 `set_offset_time()` 调整
- 接收窗口补偿：丢失 Beacon 时逐步增加补偿（1~3ms）和窗口（4ms→5ms）
- 随机避碰：A 请求使用随机延时，RTCC 数据上传也使用随机延时

**双通道机制：**
- Action 回复中提取 RF 通道号，动态切换 `channel`
- 丢失 Beacon 超过 5 次时重置通道为 0

## 7 硬件驱动分析

### 7.1 GPIO 引脚分配

| 引脚 | 端口 | 功能 | 方向 |
|---|---|---|---|
| PF3 | LED | LED 指示灯 | 推挽输出 |
| PF2 | BEEP | 蜂鸣器 | 推挽输出 |
| PA0 | CAP | 电容传感器 | LESENSE |
| PB13 | INA | 电机驱动 A | 推挽输出 |
| PB12 | INB | 电机驱动 B | 推挽输出 |
| PD14 | nSLEEP | 电机驱动休眠 | 推挽输出 |
| PC11 | KEY | 输液管检测 | 输入 |
| PB11 | KEY2 | 开盖检测 | 输入（中断） |
| PD13 | KEY3 | 到位检测 | 输入（中断） |
| PD15 | BATON | 电池检测供电 | 推挽输出 |

### 7.2 电机驱动

H 桥驱动（INA/INB/nSLEEP）：

| 操作 | INA | INB | nSLEEP | 说明 |
|---|---|---|---|---|
| 伸出 | 0 | 1 | 1 | 正转，延时 GO=1250（约 10s） |
| 回收 | 1 | 0 | 1 | 反转，延时 BACK=500（约 4s） |
| 停止 | 0 | 0 | 0 | 休眠 |

电机延时由 Cryotimer 控制（8ms 周期），到位后中断触发停止。

### 7.3 电容传感器

硬件链路：ACMP0 + LESENSE → PA0

- ACMP0：电容传感模式，VDD 高阈值 2.17V / 低阈值 1.03V
- LESENSE：通道 8（PA0），周期扫描，计数器模式，LFXO 128 分频
- 扫描周期：约 0.5Hz
- 检测逻辑：`determination()` 分析扫描结果变化量，判断输液管状态

### 7.4 低功耗管理

**能量模式：** EM2 深度睡眠（关 CPU、关 HF 外设，保留 LFXO/ULFRCO）

**唤醒源：**

| 唤醒源 | 用途 |
|---|---|
| LETIMER0 | 1 秒时基，RF 接收窗口定时 |
| Cryotimer | 电机延时控制 |
| RTCC | 数据上传周期 |
| ADC0 | 电池电压采集完成 |
| GPIO（KEY2/KEY3） | 开盖/到位检测 |
| RAIL | RF 接收中断 |

**功耗优化策略：**
1. 每次循环结束关闭 Radio 后进入 EM2
2. 关闭 SWD 调试引脚
3. ADC 按需开启/关闭
4. 接收窗口动态调整（成功 4ms，失败 5ms）
5. DC-DC Bypass 模式
6. 随机延时避免碰撞减少重发

## 8 架构总结

本项目代码架构清晰地分为三层：

1. **HAL 层**（hal-efr32/）：Silicon Labs 标准 BSP，负责芯片级初始化（时钟、DCDC、EMU）
2. **用户驱动层**（user_driver/）：封装 MCU 外设驱动（ADC、Cryotimer、LETIMER、RTCC、Flash、WDOG、GPIO 中断等）
3. **应用层**（app_driver/ + main.c + rf_process.c）：实现业务逻辑（RF 通信协议、任务调度、电池检测、电容传感、OTA 升级等）

系统的核心设计理念是 **超低功耗运行**：设备绝大部分时间处于 EM2 深度睡眠状态，由 LETIMER（1 秒周期）和 RTCC（12 秒周期）定时唤醒执行任务，通过 Sub-GHz 无线与基站保持时间同步，实现周期性的 Beacon 接收和心跳数据上报。
