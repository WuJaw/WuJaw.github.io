## 1 背景

公司工时系统是一个 Vue 3 + Element Plus 的 Web 应用，每天要手动登录填报。工作内容已经写在周报 Excel 里，重复填写效率低下，于是写了 Python 脚本自动完成提交。

源码放在 [python/submit_work_hours.py](https://github.com/WuJaw/WuJaw.github.io/blob/master/python/submit_work_hours.py)，附带[项目列表导出脚本](https://github.com/WuJaw/WuJaw.github.io/blob/master/python/export_projects.py)。

## 2 接口分析

### 2.1 抓包方式

工时系统在内网，外部工具无法直接访问。通过浏览器 F12 Console 注入拦截器来捕获请求：

```javascript
(function(){
  var origOpen = XMLHttpRequest.prototype.open;
  var origSend = XMLHttpRequest.prototype.send;
  XMLHttpRequest.prototype.open = function(){
    var xhr = this;
    xhr.addEventListener('readystatechange', function(){
      if(xhr.readyState === 4){
        console.log('[POST] ' + xhr._u + ' => ' + xhr.status);
        console.log('  Response: ' + xhr.responseText.substring(0, 500));
      }
    });
    origOpen.apply(this, arguments);
    xhr._u = arguments[1];
  };
  XMLHttpRequest.prototype.send = function(body){
    console.log('Body: ' + body);
    return origSend.apply(this, arguments);
  };
  console.log('Interceptor started');
})();
```

### 2.2 关键接口

| 接口 | 说明 | 请求体 |
|------|------|--------|
| `POST /api/dailyReport/add` | 新建日报 | 数组格式 |
| `POST /api/dailyReport/update` | 更新日报 | 对象格式，需带 `id` |
| `POST /api/dailyReport/list` | 查询日报列表 | 分页参数 |

关键差异：`add` 接口接收**数组**，`update` 接口接收**对象**且必须带 `id` 字段，否则服务端 SQL 会因缺少 `id` 限定查出大量重复记录，报 `Expected one result (or null) to be returned by selectOne()` 错误。

### 2.3 认证方式

认证通过 Cookie 完成，Cookie 格式：

```
TMS_SESSION_ID=xxxx; rememberMe=xxxx; token=111
```

其中 **`token=111` 就是用户 ID**。服务端 `dailyReport/add` 接口不校验 payload 里的 `userId`，直接以 Cookie 对应的 session 身份提交。如果 Cookie 是别人的，即使 payload 填了自己的 userId，日报也会提交到别人名下。

因此必须确保 Cookie 中的 `token` 字段和提交的 userId 一致。脚本会自动从 Cookie 的 `token=` 字段提取 userId，并通过 `/api/dailyReport/list` 反查用户姓名。

## 3 周报 Excel 结构

周报文件结构如下（Sheet 名：`周报`）：

| 星期 | 日期 | 工作状态 | 项目编码 | 工作内容 | 备注 |
|------|--------|---------|---------|---------|------|
| 周一 | 2026-01-05 | 办公 | RD240012 | 对接需求定义 | |
| 周二 | 2026-01-06 | 办公 | RD240009 | 软著材料编写 | |
| ... | ... | 法定假 | | | 休息 |

每周之间有"本周工作重点"和"下周工作计划"分隔行，脚本解析时会自动跳过（兼容分隔行出现在列0或列1的情况）。

工作状态分类：

- **工作日**：`办公`、`出差`、`外勤` → 提交 8 小时
- **休息日**：`法定假`、`周六`、`周日`、`年假`、`病假`、`调休` 等 → 跳过不提交

### 3.1 日期格式兼容

不同人的周报 Excel 日期格式可能不同：

| 格式 | 示例 | 来源 |
|------|------|------|
| datetime 对象 | `2026-01-05 00:00:00` | pandas 自动解析 |
| 横杠字符串 | `2026-01-05` | 部分手动填写的 Excel |
| 点分隔字符串 | `2026.1.1` | 部分人的 Excel |

脚本统一将 `.` 和 `/` 替换为 `-`，再用 `strptime` 解析，确保输出 `YYYY-MM-DD` 标准格式。

## 4 脚本实现

### 4.1 启动加速：三阶段加载

脚本将操作分为三个阶段，**先把所有用户输入收完，再加载重模块**：

| 阶段 | 操作 | 延迟 |
|------|------|------|
| 阶段1（秒出） | 读cookie → 确认Excel路径 → 输日期范围 | <1s |
| 阶段2（按需） | 弹 tkinter 文件对话框 | 仅首次选新文件 |
| 阶段3 | `import pandas/requests` + 网络验证 | 输完才执行 |

关键技巧：`pandas` 和 `requests` 改为**懒加载**（函数内 `import`），不在脚本顶部导入，避免启动时 3-5 秒的模块加载阻塞用户输入。

### 4.2 Cookie 输入：剪贴板读取

Windows 控制台 `input()` 有缓冲区限制，长 Cookie 字符串（含 `rememberMe` 加密数据，几百字符）粘贴时会被截断。

解决：输入 Cookie 时直接回车，脚本通过 PowerShell `Get-Clipboard` 读取系统剪贴板，完整无截断：

```python
def read_clipboard():
    """从 Windows 剪贴板读取文本"""
    import subprocess
    result = subprocess.run(
        ['powershell', '-NoProfile', '-Command', 'Get-Clipboard'],
        capture_output=True, text=True, timeout=5
    )
    return result.stdout.strip()

def input_cookie(prompt='Cookie: '):
    print('（浏览器复制Cookie后直接回车粘贴，或手动输入）')
    raw = input(prompt).strip()
    if raw:
        return raw
    # 回车 → 读剪贴板
    clip = read_clipboard()
    if clip:
        print(f'  已读取 ({len(clip)} 字符): {clip[:50]}...{clip[-20:]}')
        return clip
    return ''
```

使用流程：
1. 浏览器 F12 → Network → 复制完整 Cookie（Ctrl+C）
2. 运行脚本 → Cookie 提示时**直接回车**
3. 自动读取剪贴板，显示首尾供确认

备用方案：ctypes 调用 Win32 API（`OpenClipboard/GetClipboardData`），在 PowerShell 不可用时使用。

### 4.3 用户身份自动识别

从 Cookie 的 `token=` 字段自动提取 userId，再通过 API 反查姓名：

```python
def extract_uid_from_cookie(cookie_str):
    for part in cookie_str.split(';'):
        part = part.strip()
        if part.startswith('token='):
            val = part[6:].strip()
            if val.isdigit():
                return int(val)
    return 0

def detect_user(cookie, user_id):
    result = api_post(cookie, '/api/dailyReport/list',
                      {'pageNum': 1, 'pageSize': 1, 'userId': user_id})
    if result.get('code') == '200':
        items = result['info'].get('list', [])
        if items:
            return items[0]['userCompellation']
    return ''
```

也支持命令行参数覆盖：`--uid 114 --name 唐嘉伟`。

### 4.4 文件路径记忆

脚本记住上次使用的 Excel 路径（保存在 `last_path.txt`），二次运行直接按 `Y` 跳过文件对话框，避免 tkinter 初始化 3-5 秒的延迟。

```python
# 记住上次路径
last = load_last_path()
if last:
    print(f'上次文件: {last}')
    choice = input('使用此文件? [Y/n]: ').strip().lower()
    if choice not in ('n', 'no'):
        excel_path = last
```

### 4.5 命令行参数

支持纯命令行运行，完全跳过交互：

```powershell
# 提交某一天
python submit_work_hours.py -f "D:/周报/办公室周报2026-吴潇.xlsx" -s 0212 -e 0212

# 提交某一周
python submit_work_hours.py -f "D:/周报/办公室周报2026-吴潇.xlsx" -s 0210 -e 0214

# 指定用户
python submit_work_hours.py -f "D:/周报.xlsx" -s 0212 --uid 114 --name 唐嘉伟
```

### 4.6 PyInstaller 兼容

打包为 exe 后，`__file__` 指向临时解压目录（`sys._MEIPASS`），每次运行路径不同，导致 cookie 文件丢失。修复：

```python
if getattr(sys, 'frozen', False):
    APP_DIR = os.path.dirname(sys.executable)  # exe 所在目录
else:
    APP_DIR = os.path.dirname(os.path.abspath(__file__))  # 脚本目录
```

`cookie.txt`、`last_path.txt` 都保存在 exe 同目录，稳定可靠。

## 5 核心流程

```
读 cookie.txt → 提取 token=uid → 确认Excel路径 → 输日期范围
    → import pandas/requests → Cookie 验证 → 反查姓名
    → 解析日期/状态/项目/内容
    → 查询已有记录（区分 add / update，跳过已审核）
    → 逐条提交（间隔 0.3s）
```

## 6 踩坑记录

### 6.1 已审核记录不可修改

提交时报 `程序异常，稍后重试`，实际 API 返回的是 `info: "日报记录已审核不可修改删除!"`。原代码只看 `msg` 字段，把真实原因藏掉了。

修复：
1. 错误提示优先显示 `info`（服务端真实原因），其次 `msg`
2. `auditing == 1` 时自动跳过，输出 `SKIP` 而非尝试提交

### 6.2 Cookie 粘贴截断

Windows 控制台 `input()` 缓冲区有限，长 Cookie 粘贴时后半段丢失。表现为 Cookie 验证失败，但手动检查发现内容不完整。

修复：通过 PowerShell `Get-Clipboard` 读取剪贴板，绕过控制台缓冲区限制。

### 6.3 多用户串号

最初 `USER_ID=111` 硬编码，别人用脚本时日报全提交到了吴潇名下。根本原因：

1. 服务端没有"获取当前用户"接口
2. `add` 接口信任 payload 中的 `userId`，不做身份校验
3. 但 Cookie 中的 session 决定了实际归属——用谁的 Cookie 登录就是谁的

修复：从 Cookie 的 `token=` 字段提取真实 userId，确保身份一致。

### 6.4 Excel 日期格式不兼容

唐嘉伟的 Excel 日期是字符串 `"2026.1.1"`（点分隔），字符串比较时 `"." > "-"` 导致日期范围过滤失败，输出"范围内无记录"。

修复：统一将 `.` 和 `/` 替换为 `-`，再用 `strptime` 解析为标准 `YYYY-MM-DD`。

### 6.5 update 接口 selectOne 报错

用 `/api/dailyReport/update` 创建新记录（不带 `id`），服务端返回：

```json
{"code":"202","msg":"程序异常，稍后重试","info":"Expected one result (or null) to be returned by selectOne(), but found: 12497"}
```

解决：区分 `add`（新建，不带 `id`）和 `update`（更新，带 `id`）两个接口。

### 6.6 add 请求体是数组

`add` 接口的请求体是 JSON **数组**，每个元素代表一条日报；`update` 是单个**对象**。第一次用对象格式调 `add` 被服务端静默忽略。

```powershell
pip install pyinstaller
pyinstaller --onefile submit_work_hours.py
```

### 7.3 Cookie 获取

1. 浏览器打开工时系统 → F12 → Network 标签
2. 随便点一下页面触发请求
3. 点一个请求 → Headers → Request Headers → 复制 Cookie 值
4. 脚本运行时 Ctrl+V 复制后直接回车

**注意**：不要用 `copy(document.cookie)`，它拿不到 HttpOnly 的 Cookie（如 `rememberMe`），复制出来是不完整的。F12 Network 里看到的才是完整的。确保 Cookie 包含 `token=xxx` 字段。
