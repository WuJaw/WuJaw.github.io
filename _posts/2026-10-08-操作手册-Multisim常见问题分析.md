NI Multisim 是基于 SPICE 的电路仿真与原理图工具，日常用得顺手，但报错时往往是同一批问题反复出现。下面把高频问题按「根因 → 分步修复」整理，先给一张对照表，再逐条展开。

## 1 快速对照表

| # | 现象 | 一句话根因 | 最快修复 |
|---|------|-----------|---------|
| 1 | `Simulation convergence failed` / `Time step too small` | 电路存在病态节点，求解器步长缩到下限仍不收敛 | 放宽 `reltol`、加 `GMIN`、给关键节点串小电阻 |
| 2 | 仿真结果全为 0 / 电路完全不动 | 没接 Ground 或激励源值/极性错 | 每电路至少一个 Ground，检查电源数值 |
| 3 | 节点报「未连接」/ 仿真直接终止 | 少接地、悬空引脚、隐藏管脚未连 | 补 Ground、用「Show Hidden Pins」查悬空 |
| 4 | 元件搜不到 / 元件库为空 | 选错 Group/Series，或搜的是 User DB 而非 Master DB | 从 Master Database 搜，确认 Group 选对 |
| 5 | 示波器/万用表无读数 | 仪器没真正连到节点、触发或耦合设错 | 检查连线、改触发源、确认 DC/AC 耦合 |
| 6 | 数字/混合仿真卡死或极慢 | 数字事件驱动引擎 + 模拟边界反复交互 | 加去抖/上拉、降低仿真速率、简化数字部分 |
| 7 | 别人的工程打不开 / 报文件损坏 | 高版本存的文件低版本无法解析，或缺少自定义库 | 升级版本、让对方导出低版本、打包 User DB |
| 8 | 仿真失败且路径含中文/空格 | 部分版本对路径敏感导致网表生成异常 | 工程移到纯英文、无空格路径 |
| 9 | 元件显示「?」/ 仿真报模型缺失 | 元件库未关联 SPICE 模型或安装损坏 | 重装元件库、手动指定模型文件 |
| 10 | 仿真值与手算理论值偏差大 | 用了理想源/理想线，忽略实际参数与精度 | 检查源内阻、线损、步长与精度设置 |
| 11 | 启动报「访问数据库时发生错误 / 主数据库无法访问」 | 对数据库目录无读写权限（常见于非管理员启动） | 兼容性里勾「以管理员身份运行此程序」，以后始终管理员启动 |

## 2 仿真不收敛（Convergence Error / Time step too small）

**根因**：SPICE 求解器在某一时间步上反复迭代仍无法满足收敛判据，常见于运放/比较器构成的强反馈回路、未加限幅的开关电路、两个不同数量级阻抗直接对接。它会先把步长不断缩小，缩到下限仍不行就抛错。

**分步修复**：
1. 打开 `Simulate → Interactive Simulation Settings`（或仿真配置文件），把 `Relative Tolerance (reltol)` 从默认 0.001 放宽到 0.01。
2. 给存在不连续切换的节点（如比较器输出、开关两端）串一个 1Ω~100Ω 的小电阻，消除「瞬时突变」。
3. 在 `Analysis → ... Options` 里调大 `GMIN`（默认 1e-12，可试 1e-9），给二极管/三极管结加最小导纳，帮助求解器起步。
4. 对强反馈运放电路设置初始条件：`Place → Set Initial Conditions`，给关键节点一个合理初值。
5. 仍不行则改用 `Transient` 分析的 `Initial Conditions = Set to zero` 或 `User-defined`，并适当减小最大步长。

---

## 3 仿真结果全为 0 / 电路完全不动

**根因**：最典型是整张图没有接地（Ground），求解器没有参考电位，所有节点浮空，结果全 0；其次是激励源（DC/AC 源、函数发生器）数值为 0、极性接反，或瞬态仿真时间窗口设得过短看不到变化。

**分步修复**：
1. 确认原理图里有至少一个 `Source → Power → Ground`（0 电位参考点），且每个独立电源回路都闭合。
2. 双击激励源，确认幅值/偏置不是 0，函数发生器确认波形与频率。
3. 瞬态仿真：`Analysis → Transient` 里把 `TSTOP` 设到能覆盖信号周期的量级（如 1 kHz 信号至少设 5 ms）。
4. 用万用表「DC Voltage」点测几个节点，定位是「全图不动」还是「某支路无压」。

---

## 4 节点报「未连接」/ 仿真直接终止

**根因**：悬空引脚、未接地的子电路、运放/门电路供电脚没连（很多数字/模拟 IC 的 VCC/GND 是隐藏管脚，不连也会报未连接）。

**分步修复**：
1. `Options → Sheet Properties → Net Names` 打开 `Show All`，肉眼扫一遍有没有红叉节点。
2. 右键元件 → `Show Hidden Pins`，把 VCC/GND 补上。
3. 子电路/层次块：检查端口（Connector）是否两边都有对应连接。
4. 复用「ERC」：`Tools → Electric Rules Check`，先消掉未连接错误再跑仿真。

---

## 5 元件搜不到 / 元件库为空

**根因**：搜索范围默认可能在 `User Database` 或某个特定 `Group/Series`，而你要的元件在 `Master Database` 的另一组里；也可能数据库未完整加载（安装/汉化问题）。

**分步修复**：
1. 在元件选择框顶部把数据库切到 **Master Database**，再选对 `Group`（如 `Basic`、`Sources`、`Transistors`、`TTL`、`CMOS`）和 `Series`。
2. 用 `Search` 时只填关键字（如 `2N3904`、`LM358`、`RESISTOR`），不要同时限定 Series。
3. 若整库为空：重装/修复 Multisim 元件数据库，或检查安装目录下 `circuit` 数据库文件是否损坏。
4. 自定义元件：放到 `User Database` 并勾选「Add to favorites」，避免每次重搜。

---

## 6 虚拟仪器无读数（示波器/万用表/逻辑分析仪）

**根因**：仪器探针没真正接到节点（只是靠近）、示波器触发源/电平设错、万用表设成了交流耦合而信号是直流、逻辑分析仪采样率过低。

**分步修复**：
1. 确认仪器端子与电路节点有电气连线，不是「视觉重叠」。
2. 示波器：`Trigger` 选 `Edge` + 正确通道，触发电平设在信号幅值范围内；先切 `Auto` 触发模式确认有波形。
3. 万用表：直流信号把 `Type` 设成 `DC`，交流信号才设 `AC`。
4. 逻辑分析仪：`Clock` 设到高于信号频率至少 10 倍，否则采不到。

---

## 7 数字 / 混合模式仿真卡死或极慢

**根因**：Multisim 数字部分走事件驱动引擎，和模拟部分在 AD/DA 边界反复交互；未上拉/未去抖的输入会触发海量状态翻转，主仿真循环被拖死。

**分步修复**：
1. 数字输入端尽量加上拉/下拉电阻，避免悬空导致的无效翻转。
2. 在 `Simulation Settings` 里降低数字仿真最大速率（Maximum timestep for digital）。
3. 减少同时仿真的数字器件数量，或先把模拟部分跑通再叠加数字。
4. 混合信号（如比较器输出进 FPGA/CPLD）注意两边参考地一致。

---

## 8 别人的工程打不开 / 报文件损坏

**根因**：高版本 Multisim（如 14.x）保存的文件，低版本（如 13/12）无法解析布局与模型；或工程引用了对方机器上的自定义元件库（User DB），你这边没有。

**分步修复**：
1. 确认本机版本 ≥ 对方保存版本；不够就升级。
2. 让对方 `File → Save As` 时选「向前兼容」的低版本格式，或导出为 `Circuit Design File (.cir)` 网表再重建。
3. 对方把用到的自定义元件从 `User Database` 导出（`.ms14` / 库文件），你导入后再打开工程。
4. 损坏文件：尝试 `File → Open` 时勾选「Recover」或用备份 `.bak`。

---

## 9 路径含中文 / 空格导致仿真失败

**根因**：Multisim 生成临时网表时会把工程路径拼进命令行，部分版本对中文、空格、特殊字符敏感，导致网表路径解析失败、仿真静默退出。

**分步修复**：
1. 把工程移到纯英文、无空格的路径，如 `D:\Multisim\Projects\`。
2. 工程名和父目录都避免中文、括号、井号。
3. 重新打开工程再仿真，若之前已生成坏缓存，先删掉工程目录下的临时文件再跑。

---

## 10 元件显示「?」/ 仿真报模型缺失

**根因**：元件符号和 SPICE 模型未正确关联，常见于手动添加的三极管/运放、或从旧版本迁移的库；也可能是元件库安装不完整。

**分步修复**：
1. 双击元件 → `Value → Edit Model`，确认模型语句存在且语法正确。
2. 模型缺失时，从厂商官网下载对应 `.lib`/`.mod`，用 `Tools → Component Wizard` 重新关联。
3. 整库损坏：运行安装程序的「Repair」修复元件数据库。
4. 自建模型文件放在固定英文路径，避免再次丢失引用。

---

## 11 仿真值与手算理论值偏差大

**根因**：仿真用的是「理想模型」但手算假设了理想源/理想线；或精度设置（步长、reltol）太粗，或忽略了一致性偏差（温漂、失调电压）。

**分步修复**：
1. 检查电源是否带内阻、连线是否引入了非预期电阻（敷铜/线长）。
2. 提高精度：`reltol` 回到 0.001，`Transient` 最大步长调小一个数量级再对比。
3. 运放电路把输入失调电压（Vos）、偏置电流（Ib）纳入模型后再算。
4. 理论值是「数量级参考」还是「精确目标」要先分清，仿真更接近真实器件而非理想公式。

---

## 12 启动报「访问数据库时发生错误 / 主数据库无法访问」

**根因**：Multisim 启动时要读写元件/仿真主数据库（通常位于 `C:\ProgramData\National Instruments\Circuit Design Suite\...` 或安装目录下），在标准用户权限下对该目录没有足够权限，主数据库加载失败，依赖它的元件搜索、放置等功能全部不可用。**这不是文件损坏，而是权限问题**。

**分步修复**：
1. 关闭 Multisim。
2. 右键 `Multisim.exe`（或开始菜单里的快捷方式）→「属性」→「兼容性」选项卡。
3. 勾选 **「以管理员身份运行此程序」(Run this program as administrator)**，点「应用」→「确定」。
4. 重新启动 Multisim，数据库访问错误应消失，主数据库功能恢复。
5. 若仍报错：检查 `C:\ProgramData\National Instruments\...` 目录的 NTFS 权限，给当前用户加「完全控制」；并确认杀软或企业策略未拦截该目录读写。

> 注意：右键「以管理员身份运行」只能解决**这一次**；要做到「以后一直」，必须勾选兼容性里的「以管理员身份运行此程序」选项（或给快捷方式「高级」里设始终以管理员运行），这样每次双击都会提权启动。

---

## 13 小结

多数 Multisim 故障集中在三类：**参考地/连接问题（2、3、8）**、**求解器收敛问题（1、10）**、**库与版本问题（4、7、9）**。排障顺序建议：先 ERC 查连接 → 补地 → 放宽收敛 → 查库与版本。数字/混合仿真慢基本都是边界交互和悬空输入（6）。
