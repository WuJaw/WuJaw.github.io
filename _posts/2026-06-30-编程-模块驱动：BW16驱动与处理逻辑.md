## 1 概述

本文档描述 CH592F 平台上 BW16 WiFi 模块的完整驱动与处理逻辑，包括：

- 硬件接口（UART1 + EN 引脚）
- 统一状态机（BLE 配网 → WiFi 连接 → TCP 数据发送）
- BLE JSON 配网协议解析与响应
- BLE 广播数据接收过滤、打包与 WiFi 上传

## 2 硬件接口

### 2.1 引脚定义

| 信号   | CH592F 引脚 | 方向     | 说明                       |
| ------ | ----------- | -------- | -------------------------- |
| TXD1   | PA9         | 输出     | UART1 发送 → BW16 RX       |
| RXD1   | PA8         | 输入     | UART1 接收 ← BW16 TX       |
| EN     | PA12        | 输出     | BW16 使能脚，低电平复位    |

### 2.2 UART 配置

- 波特率：115200 bps  
- 数据位：8，停止位：1，无校验  
- 使能接收中断 `RB_IER_RECV_RDY`（通过 `UART1_INTCfg` 设置）

### 2.3 初始化代码

```c
/* BSP/bw16.h */
#define BW16_EN_PIN    GPIO_Pin_12
#define BW16_EN_SET()  GPIOA_SetBits(BW16_EN_PIN)
#define BW16_EN_CLR()  GPIOA_ResetBits(BW16_EN_PIN)

void BW16_UART1_Init(void)
{
    GPIOA_SetBits(bTXD1);
    GPIOA_ModeCfg(bTXD1, GPIO_ModeOut_PP_5mA);
    GPIOA_ModeCfg(bRXD1, GPIO_ModeIN_PU);
    UART1_DefInit();
    UART1_BaudRateCfg(115200);
    UART1_INTCfg(ENABLE, RB_IER_RECV_RDY);
    PFIC_EnableIRQ(UART1_IRQn);
}

void BW16_EN_init(void)
{
    GPIOA_ModeCfg(BW16_EN_PIN, GPIO_ModeOut_PP_5mA);
    BW16_EN_SET();
}
```

## 3 接收中断与帧完成检测

UART1 中断将收到的字节追加到 `rx_buf[512]` 中，同时记录最后一次接收的时刻 `rx_last_tick`。

```c
__INTERRUPT
void UART1_IRQHandler(void)
{
    uint8_t ch;
    if ((R8_UART1_IIR & RB_IIR_INT_MASK) == UART_II_RECV_RDY ||
        (R8_UART1_IIR & RB_IIR_INT_MASK) == UART_II_RECV_TOUT)
    {
        while (R8_UART1_LSR & RB_LSR_DATA_RDY)
        {
            ch = R8_UART1_RBR;
            if (rx_cnt < sizeof(rx_buf) - 1)
            {
                rx_buf[rx_cnt++] = ch;
                rx_last_tick = now;
            }
            else
                rx_flag = 1;
        }
    }
}
```

`bw16_task()` 主循环中每次调用都检测帧完成：若 10ms 内 `rx_cnt` 未增加则认为一帧完毕，置 `rx_flag = 1`，通知状态机处理。

```c
/* 帧完成检测（bw16_task 内）*/
if (rx_cnt != rx_cnt_last)
    rx_cnt_last = rx_cnt;
else if (rx_cnt > 0 && !rx_flag)
    if ((now - rx_last_tick) >= BW16_RX_IDLE_TIMEOUT_10MS)   // 1 × 10ms
        rx_flag = 1;
```

## 4 统一状态机

全部流程使用一个枚举变量 `state` 管理，覆盖 BLE 初始化、BLE JSON 配网等待、WiFi 连接建立和 TCP 数据发送四个阶段。

### 4.1 状态枚举

```c
enum {
    e_bw16_init = 0,         // AT 探活
    e_bw16_ATE0,             // 关闭命令回显
    e_bw16_ble_close,        // AT+BLEMODE=9（关闭 BLE）
    e_bw16_ble_name,         // AT+BLENAME=...
    e_bw16_ble_auth,         // AT+BLEAUTH=DISENABLE
    e_bw16_ble_trans_enter,  // AT+TRANSENTER=0,0
    e_bw16_ble_open,         // AT+BLEMODE=0（打开 BLE）
    e_bw16_ble_json_wait,    // BLE JSON 配网等待
    e_bw16_WMODE,            // AT+WMODE=1,0（STA 模式）
    e_bw16_DHCP,             // AT+WSDHCP 配置
    e_bw16_AT_SOCKETRECVCFG, // AT+SOCKETRECVCFG=1
    e_bw16_AT_STAINFO,       // AT+STAINFO? 查询连接状态
    e_bw16_AT_Connection,    // AT+WJAP / AT+WJEAP 连接 AP
    e_bw16_AT_IF_SOCNET,     // AT+SOCKET 查询已有连接
    e_bw16_AT_DESOCNET,      // AT+SOCKETDEL 删除旧连接
    e_bw16_AT_SOCNET,        // AT+SOCKET=4,... 建立 TCP
    e_bw16_WIFI_WORK,        // WiFi 数据发送（非阻塞工作态）
};
```

### 4.2 状态流转图

```
上电
  │
  ▼
e_bw16_init ──AT─► ATE0 ──► ble_close ──► ble_name ──► ble_auth
  ──► ble_trans_enter ──► ble_open
         │
    wifi_config==0 ?
    是 ▼              否 ▼
  ble_json_wait      e_bw16_WMODE
    │ (BLE JSON 配网)    │
    └──────────────────►─┘
                         ▼
                       WMODE ──► DHCP ──► SOCKETRECVCFG
                         ──► STAINFO
                              │
                       WiFi 已连? ────是───► IF_SOCNET
                              │否
                              ▼
                           Connection
                          (WJAP/WJEAP)
                              │+EVENT:WIFI_CONNECT
                              ▼
                           IF_SOCNET
                              │有旧 socket
                              ├──────────► DESOCNET ──► STAINFO
                              │无旧 socket
                              ▼
                           SOCNET (建立 TCP)
                              │connect success ConID=N
                              ▼
                           WIFI_WORK（持续非阻塞发送）
```

### 4.3 跨状态通用事件处理

每次 `StateTransition()` 进入时，**优先处理以下三类异步事件**，不区分当前所在状态：

| 事件关键字              | 处理动作                         |
| ----------------------- | -------------------------------- |
| `"\r\nready\r\n"`       | BW16 自发复位，状态机回到 `init` |
| `"+EVENT:WIFI_DISCONNECT"` | WiFi 断开，回到 `STAINFO` 重连  |
| `"+DATA:N,{...}"`       | BLE JSON 数据到达，解析并响应    |

### 4.4 错误恢复

- 普通 AT 命令：1 s 超时重发，累计 10 次后调用 `BW16_Reset()` 硬件复位
- WiFi 连接状态下：检测到 BW16 启动横幅 `ready` 自动重启状态机

## 5 BLE 配网（JSON over BLE）

### 5.1 流程

```
手机 APP ──BLE 写──► BW16 ──+DATA:N,JSON──► CH592F
CH592F 解析 JSON ──────────────────────────────────
CH592F 生成响应 ──AT+BLESENDRAW=N──► BW16 ──►(>) ──► CH592F 发正文 ──► 手机
```

### 5.2 JSON 帧解析（bw16_parse_data_frame）

BW16 推送格式：`+DATA:<len>,<json_body>`

```c
static uint16_t bw16_parse_data_frame(
    const uint8_t* buf, uint16_t len,
    uint8_t* json_out, uint16_t json_out_len)
{
    const uint8_t* p = (const uint8_t*)strstr((const char*)buf, "+DATA:");
    if (!p) return 0;
    p += 6;                         // 跳过 "+DATA:"
    uint16_t data_len = 0;
    while (*p >= '0' && *p <= '9')  // 解析长度
        data_len = data_len * 10 + (*p++ - '0');
    if (*p++ != ',') return 0;      // 跳过逗号
    if (data_len == 0 || data_len > json_out_len - 1) return 0;
    if (len - (p - buf) < data_len) return 0;  // 数据不完整
    memcpy(json_out, p, data_len);
    json_out[data_len] = '\0';
    if (json_out[0] != '{') return 0;
    return data_len;
}
```

### 5.3 JSON 协议格式

**读取配置（C→S）：**

```json
{"cmd":"read","seq":1,"data":{"parameter":"wifi sta"}}
{"cmd":"read","seq":2,"data":{"parameter":"local info"}}
{"cmd":"read","seq":3,"data":{"parameter":"remote info"}}
```

**写入配置（C→S）：**

```json
{"cmd":"write","seq":4,"data":{
  "parameter":"wifi sta",
  "wifi mode":"personal",
  "ssid":"MyWiFi",
  "pwd":"password123"
}}
```

```json
{"cmd":"write","seq":5,"data":{
  "parameter":"local info",
  "dhcp":"enable"
}}
```

```json
{"cmd":"write","seq":6,"data":{
  "parameter":"remote info",
  "ip":"192.168.1.100",
  "port":6000
}}
```

**执行操作（C→S）：**

```json
{"cmd":"exec","seq":7,"data":{"opcode":1}}   // 确认保存配置
{"cmd":"exec","seq":8,"data":{"opcode":2}}   // 清除所有WiFi配置
```

**响应（S→C）：**

```json
{"cmd":"respond","data":{"parameter":"wifi sta","net sta":"offline",
  "wifi mode":"personal","ssid":"MyWiFi","pwd":"...","bssid":"0.1.2.3.4.5",
  "secy":"0","id":""},"seq":1,"message":"success"}
```

### 5.4 WiFi 信息数据结构

```c
typedef struct {
    uint8_t wifi_mode;      // 0: 个人模式, 1: 企业模式
    uint8_t ssid[32];       // WiFi SSID
    uint8_t pwd[32];        // WiFi 密码
    uint8_t bssid[6];       // 指定 BSSID（全0表示不指定）
    uint8_t security;       // 企业认证类型 1:PEAP 2:TLS 3:TTLS 4:FAST
    uint8_t identity[32];   // 企业认证用户名
    uint8_t dhcp;           // 0: 静态 IP, 1: DHCP
    uint8_t ip[4];          // 本地 IP
    uint8_t mask[4];        // 子网掩码
    uint8_t gateway[4];     // 网关
    uint8_t remote_ip[4];   // 服务器 IP
    uint8_t remote_port[2]; // 服务器端口（大端）
    uint8_t reserve;        // 字节对齐
} bw16_info_s;
```

配置信息存储在 CH592F DataFlash 偏移 `0x0100` 处（`BW16_ADD`）。

### 5.5 BLE JSON 等待态子步骤

```
json_wait_step=0  →  空闲，等待 +DATA: 触发
json_wait_step=1  →  已发 AT+BLESENDRAW=N，等待 BW16 返回 ">"
json_wait_step=2  →  收到 ">"，发 JSON 正文；配网完成后分流：
                      wifi_now_config==1 → e_bw16_init（复位重连）
                      wifi_now_config==0 → e_bw16_WMODE（不复位）
```

## 6 WiFi 连接建立

### 6.1 AT 命令序列

| 步骤                  | AT 命令示例                                           | 说明                          |
| --------------------- | ----------------------------------------------------- | ----------------------------- |
| 设置 STA 模式         | `AT+WMODE=1,0`                                        | 模式1=STA，0=不自动连接       |
| 配置 DHCP / 静态 IP   | `AT+WSDHCP=1` 或 `AT+WSDHCP=0,IP,MASK,GW`            | 取决于 dhcp 字段              |
| 配置接收完整包        | `AT+SOCKETRECVCFG=1`                                  | 每包含完整数据                |
| 查询连接状态          | `AT+STAINFO?`                                         | 返回 `+STAINFO:N`，N=3 已连接 |
| 连接 AP（个人模式）   | `AT+WJAP=<ssid>,<pwd>`                                | 等待 `+EVENT:WIFI_CONNECT`    |
| 连接 AP（企业模式）   | `AT+WJEAP=<secy>,<ssid>,<id>,<pwd>`                   | 同上                          |
| 查询已有 socket       | `AT+SOCKET`                                           | 返回列表，有逗号则有旧连接    |
| 删除旧 socket         | `AT+SOCKETDEL=<id>`                                   | 清理后重新查询                |
| 建立 TCP 连接         | `AT+SOCKET=4,<remote_ip>,<port>,7200`                 | 等待 `connect success ConID=N`|

### 6.2 STAINFO 响应解析

```c
int sta = 0;
char* bf = strstr((char*)rx_buf, "+STAINFO:");
sscanf(bf, "+STAINFO:%1d", &sta);
// sta==3 → 已连接，进 IF_SOCNET
// sta==0/4 → 未连接，进 Connection
```

## 7 WiFi 数据发送（非阻塞）

### 7.1 发送接口

外部模块调用 `bw16_wifi_send()` 放入发送队列，状态机后台完成发送：

```c
uint8_t bw16_wifi_send(const uint8_t* data, uint16_t len);
// 返回 1: 成功放入队列
// 返回 0: 未连接 / 上次发送未完成 / 参数非法
```

### 7.2 发送子步骤

```
wifi_send_step=0  →  发 AT+SOCKETSEND=<con_id>,<len>
wifi_send_step=1  →  等待 ">" 提示符
wifi_send_step=2  →  收到 ">"，发送 wifi_send_buf 数据体
wifi_send_step=3  →  等待 "OK" 确认发送完成
```

超时（100 × 10ms = 1 s）自动回到步骤 0 重试。

## 8 BLE 广播接收与数据打包

### 8.1 整体流程

```
CH592F BLE 硬件 ──► RF_PHY 回调 ──► raw_msg 队列
radio_process_init()  ──► Radio_ProcessEvent() 轮询
  └── bt_msg_analysis() / proprietary_msg_analysis()
        └── build_bt_rx_packet() → valid_msg 队列
              └── bw16_wifi_send()（满10条批量发送）
```

### 8.2 BLE 数据帧过滤（bt_msg_filter）

仅接受符合昂科私有广播协议的数据帧：

| 偏移 | 期望值 | 说明                     |
| ---- | ------ | ------------------------ |
| [0]  | 0x02   | ADV_NONCONN_IND          |
| [1]  | 0x25   | 总长度 37 字节           |
| [8]  | 0x02   | Flag 字段长度            |
| [9]  | 0x01   | Flag 类型                |
| [11] | 0x1B   | 厂商数据长度 27           |
| [12] | 0xFF   | 厂商数据类型             |
| [13] | 0xC7   | 公司 ID 低字节（昂科）   |
| [14] | 0x00   | 公司 ID 高字节           |
| [15] | 0x01 / 0xF0 | 方向发现包 / 信息包 |

方向发现包（`0x01`）进一步验证 DF Field（16字节 UUID）并校验 CRC8：

```c
check_value = cal_crc_table(&rxbuf[16], 8);
if (check_value == rxbuf[24])  // 通过
```

### 8.3 数据打包格式（build_bt_rx_packet）

**方向发现包 / 信息包 → `CMD_BT_IBEACON (0x60)` 格式：**

| 字节  | 内容                | 说明                   |
| ----- | ------------------- | ---------------------- |
| [0]   | 0xFF                | 帧头                   |
| [1]   | LEN_BT_IBEACON(13)  | 总长度（含自身）        |
| [2]   | 0x60                | 命令字                 |
| [3~6] | Tag PartNo (4B)     | 标签序列号             |
| [7]   | Sequence            | 广播序列号             |
| [8]   | Index               | 数据类型索引           |
| [9~11]| Content[0~2]        | 内容（版本/电量/事件） |
| [12]  | RSSI                | 信号强度               |
| [13]  | CheckSum            | 累加和校验             |

**私有协议包 → `CMD_PROPRIETARY_DATA (0x62)` 格式：**

| 字节   | 内容             |
| ------ | ---------------- |
| [0]    | 0xFF             |
| [1]    | rxbuf[1]+3       |
| [2]    | 0x62             |
| [3..N] | 原始数据体       |
| [N+1]  | CheckSum         |

### 8.4 批量发送策略

`Radio_ProcessEvent()` 中：
- valid_msg 队列积累满 **10 条**消息后批量调用 `bw16_wifi_send()`
- 发送失败时用 `queue_write_batch()` 写回队列，不丢数据

## 10 时基说明

BW16 状态机统一使用 BLE 协议栈内部时钟作为时基：

```c
uint32_t bw16_get_10ms_count(void) {
    return TMOS_GetSystemClock() / 16;
}
// TMOS_GetSystemClock() 单位 0.625ms，除以 16 得到 10ms 计数
```

各超时参数：

| 场景              | 超时值（10ms 单位）| 实际时间 |
| ----------------- | ----------------- | -------- |
| 普通 AT 命令      | 100               | 1 s      |
| WiFi 连接等待     | 2000              | 20 s     |
| TCP 建立等待      | 200               | 2 s      |
| WiFi 发送超时     | 100               | 1 s      |
| BLE 响应重试      | 1000              | 10 s     |
| 接收帧完成检测    | 1                 | 10 ms    |
